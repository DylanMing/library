
大小端问题，也称为字节序问题，是指在计算机系统中表示多字节数据类型（如整数、浮点数等）时，字节的排列顺序问题。这个问题主要出现在不同架构的计算机之间进行数据交换时，尤其是当这些计算机的内部表示方式不一致时。

在计算机系统中，我们是以字节为单位的，每个地址单元都对应着一个字节，一个字节为8bit。但是在C语言中除了8bit的char之外，还有16bit的short型，32bit的long型（要看具体的编译器），另外，对于位数大于8位的处理器，例如16位或者32位的处理器，由于*寄存器宽度大于一个字节*，那么必然存在着一个如何将多个字节安排的问题。因此就导致了大端存储模式和小端存储模式。例如一个16bit的short型x，在内存中的地址为0x0010，x的值为0x1122，那么0x11为高字节，0x22为低字节。对于大端模式，就将0x11放在低地址中，即0x0010中，0x22放在高地址中，即0x0011中。小端模式，刚好相反。我们常用的X86结构是小端模式，而KEIL C51则为大端模式。很多的ARM，DSP都为小端模式。有些ARM处理器还可以由硬件来选择是大端模式还是小端模式。

# 历史故事

大端和小端来自一个小故事：端模式(Endian)的这个词出自Jonathan Swift书写的《格列佛游记》。这本书根据将鸡蛋敲开的方法不同将所有的人分为两类，从圆头开始将鸡蛋敲开的人被归为Big Endian，从尖头开始将鸡蛋敲开的人被归为Littile Endian。小人国的内战就源于吃鸡蛋时是究竟从大头(Big-Endian)敲开还是从小头(Little-Endian)敲开。在计算机业Big Endian和Little Endian也几乎引起一场战争。




# 端序的分类

1. **大端（Big-Endian）**：在大端模式下，多字节数据的最高有效字节（MSB）存储在最低的内存地址，其余字节按顺序排列。例如，一个16位的数字`0x1234`在大端存储中会先存储`0x12`，然后是`0x34`。
2. **小端（Little-Endian）**：在小端模式下，最低有效字节（LSB）存储在最低的内存地址，其余字节顺序相反。同样的16位数字`0x1234`在小端存储中会先存储`0x34`，然后是`0x12`。

例子：
数字 `0x12 | 34 | 56 | 78`

大端模式：
```
低地址 -----------------> 高地址  
0x12 | 0x34 | 0x56 | 0x78
```
小端模式：

```
低地址 ------------------> 高地址  
0x78 | 0x56 | 0x34 | 0x12
```

所以可以看到，大端就是类似从左往右的阅读顺序由低位到高位（大端模式和字符串的存储模式类似），小端就是类似从右往左的阅读顺序由高位到低位。



# 大小端问题的影响
1. **数据一致性**：在网络通信或文件存储中，如果发送方和接收方的计算机架构不同，那么直接交换数据可能会导致数据解释错误，从而影响数据的一致性和准确性。
2. **跨平台开发**：在进行跨平台软件开发时，开发者需要考虑到大小端问题，确保数据在不同平台上能够正确解释和处理。
3. **性能优化**：某些架构可能在大端或小端模式下有更好的性能表现，这可能会影响硬件设计和软件优化的选择。
    

# 如何处理大小端问题
为了解决大小端问题，通常会采用以下方法：
1. **标准化协议**：在网络协议或数据交换格式中明确规定使用网络字节序（大端序），确保数据在不同架构之间传输时能够正确解释。
2. **字节序转换**：在软件中实现字节序转换函数，将数据从一种端序转换为另一种端序，以适应不同的计算机架构。
3. **硬件支持**：某些处理器提供了硬件级别的字节序转换指令，可以高效地处理大小端问题。
